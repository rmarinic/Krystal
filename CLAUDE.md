# CLAUDE.md — Krystal

## Overview
- **Krystal** is a native Windows desktop chat application for **Claude Code** — it wraps the `claude` CLI in a clean graphical UI so users get a proper app experience instead of the terminal.
- **Stack:** Tauri 2 — Rust backend in `src-tauri/` + vanilla HTML/CSS/JS frontend in `src/`. No framework, no bundler.
- **Audience/goal:** make Claude Code pleasant for everyone, including non-technical users. Originally single-purpose; now being generalized to support **any** project type (writing / research / code / data).
- **Status:** functional and shipping at **v0.3.0**; releases automated via GitHub Actions.

## Architecture (keep this split)
- `src-tauri/claude.rs` — builds the CLI invocation and turns its stream-json output into UI events. `base_args` + `apply_mode` + `apply_chat_flags` + `apply_session_flags` assemble the flags: the system prompt spilled to a file, `--effort`, `--fallback-model` (an overloaded model degrades instead of failing the turn), `--autocompact auto`, `--add-dir` for each folder the project has been granted beyond its own, `--mcp-config` for the artifact tool (see `artifacts.rs`; deliberately *not* `--strict-mcp-config`, which would switch off the user's own MCP servers), and in orchestrator mode the worker sub-agents defined inline via `--agents`. `build_prompt` assembles the turn's message: background context (task note, compact seed, #-referenced chats, attached files) leads — **except** when the message opens with `/skill-name`, which the CLI only resolves at the very head of a prompt, so those messages lead and their background follows. `run_turn` drives one turn on a warm session and ends at its `result` event.
- `src-tauri/artifacts.rs` — **artifacts**: the self-contained documents Claude builds (a page, a drawing, a report) that open in a panel beside the conversation instead of as a code block inside it. The `claude` binary has no Artifact tool of its own — that is something the *host* application provides — so Krystal hands the session one, over MCP (`--mcp-config`), and it appears in the toolset as `mcp__krystal__artifact`. The MCP server is **this same executable** re-launched with `MCP_FLAG` (`--krystal-mcp-artifacts`), speaking JSON-RPC on stdio; `claude` starts it, Krystal never talks to it. It is the only thing that applies an `old_str`/`new_str` patch, and it writes the resolved document under `KRYSTAL_ARTIFACT_DIR`. Krystal picks the content up from the `tool_use`/`tool_result` events `claude.rs` already parses, so there is one implementation of the patch logic and no IPC bridge to a grandchild process. The content never travels back through the tool's *result* — that would re-inject the whole document into Claude's context on every revision.
- `src-tauri/session.rs` — **persistent per-chat `claude` processes**. A chat is served by one `--input-format stream-json` process: each message is a JSON line on its stdin, so the session id, the loaded context and the prompt cache survive between turns instead of being rebuilt with `--resume` every time. Everything passed as a flag is fixed at spawn, so the flags form the session **key** — changing model/mode/effort/orchestrator (or compacting, clearing, moving the project) retires the process and the next message starts a fresh one. Stop is two-step: the first press is a `control_request`/`interrupt`, not a kill, so a stopped turn keeps its session — but an interrupt is only a *request*, and a turn wedged in a tool run may never honour it, so a second press (or the frontend's escalation timer) makes `stop_chat` retire the session and kill the process tree. `Pool` caps warm sessions (`MAX_WARM_SESSIONS`) and retires idle ones (`IDLE_TIMEOUT_SECS`); everything is retired on app exit.
- **Per-turn context can't go in the system prompt** — that's fixed at spawn. Anything that varies per turn (today: the task-list note) rides on the user message via `claude::build_prompt`'s `notes` argument.
- `src-tauri/commands.rs` — Tauri command handlers exposed to the frontend. One-off calls whose reply is parsed as JSON (task generation, the Initialize wizard) pin the shape with `--json-schema`; `extract_json` stays as the safety net.
- `src-tauri/db.rs` — SQLite persistence for chats/projects. A turn is written in three beats rather than one, so nothing is lost if the app goes away mid-answer: `begin_turn` saves the user's message *before* Claude is asked anything (and gives an unnamed chat its fallback title there and then), `save_partial` re-writes the answer as it streams (throttled by `claude::PARTIAL_SAVE_MS`), and `finish_turn` completes those same rows and rolls up the totals. A turn that produced nothing (stopped early, session refused to start) ends at `abort_turn`, which keeps the message and drops the empty answer. Rows carry a `partial` flag while the turn is in flight — one left set is a turn the app never finished, and the UI badges it as interrupted.
- `src-tauri/server.rs` — **phone access**: an opt-in HTTP/SSE server on the LAN (hyper, `0.0.0.0:7420`) that serves the touch UI embedded from `src-tauri/src/webui/` and fronts the *same* command functions the window invokes — so a phone is a second view of one app, not a second app. A six-digit PIN (new per start, ten wrong guesses and it locks) is traded for a bearer token; only the shell is public. A turn streams back as SSE by handing `commands::chat` a `Channel::new` whose handler writes into the response body, and the same events are mirrored to the desktop window (`remote-turn-start`/`remote-turn`) so an open chat paints a phone turn live. Generic over the Tauri runtime so the whole server can be stood up against a mock app in its tests. Also here: the **firewall check** (`firewall_status`/`firewall_allow`) — loopback is never filtered, so a Windows Firewall that drops every packet from the phone leaves the host looking perfectly healthy and tells no one. `netsh` is asked whether any inbound rule names this exe (paths aren't localised, so searching the dump works in any Windows language), and the Remote panel's firewall row offers to add one: an elevated helper `.ps1` (UTF-8 **with BOM**, or PowerShell 5.1 reads it as the system codepage) writes a program-scoped `profile=any` rule through a single UAC prompt. The exe path is what a rule is keyed by, so a dev build being allowed says nothing about the installed one.
- `src/app/` — the frontend UI logic, split into cohesive **classic scripts that share one global scope** (no bundler/modules). They load in order via `<script defer>` (see `index.html`); a symbol declared in an earlier file is visible to all later ones, so **load order matters** and `boot.js` (the entry point) loads last. Layout: `core` (IPC/`els`/`state`/`api`/utils) → `sidebar` → `chat` → `projects` → `controls` → `activity` → `agents` → `search` → `messages` → `artifacts` → `stream` → `mentions` → `skills` → `wizard` → `localization` → `settings` → `git` → `links` → `logo` → `usage` → `boot`. See `src/app/core.js` for the full map.
- `src/i18n.js`, `src/onboarding.js`, `src/updater.js` — i18n dictionary, first-run onboarding, and self-update (load before the `app/` modules).
- Self-updates ship via **GitHub Releases**.

## Frontend file map (where to find things)
Loaded in this order; each file may use symbols from any earlier one (shared global scope).
- `src/i18n.js` — EN/HR string dictionary + `window.I18N` (`t`/`getLang`/`setLang`); fires `i18n:changed`.
- `src/onboarding.js` — first-run gate: install Claude Code + sign-in flow (own IIFE scope).
- `src/updater.js` — self-update overlay (check GitHub Releases, download, install).
- `src/app/core.js` — foundation: Tauri IPC handles, `$`, `tr`, the `els` element map, `state`, context-window constants, the `api` wrapper, and shared utils (`basename`, `escapeHtml`, `closeOverlay`/`openOverlay`, `replayClass`, `cssEsc`, …).
- `src/app/sidebar.js` — thread list rendering, inline rename, search/saved results list.
- `src/app/chat.js` — thread view (`openThread`/`showEmpty`), usage meter + context-rot tips, message bubbles (`appendMessage`), star/favorite. `openThread` skips the rows of a turn that is still live (the backend names the first one on a `saved` event, kept as `live.savedFrom`) because the live view paints those itself; a row still flagged `partial` on reload wears an "Interrupted" badge.
- `src/app/projects.js` — project picker (entry screen), `startNewChat`, welcome-screen Initialize/Reinitialize, the **folders panel** (the project path under the chat title opens it: the project folder plus any extra folders granted to it, each passed as `--add-dir`; stored in the SQLite `project_dirs` table and re-keyed by `move_project` like pins), and **change a project's folder** (`moveProjectFolder` → `move_project`: the project keeps its chats/tasks/run command, which the backend re-keys from the old path to the new one; each moved chat's `session_id` is dropped because Claude Code keys its own sessions by working directory).
- `src/app/controls.js` — model/mode/**effort** pickers (`createPicker`), compact/clear/hint actions, the compact/clear progress overlay. Effort is `claude --effort` (low→max, default `high`), remembered per chat like the model and the mode.
- `src/app/activity.js` — Activity panel: live shells & sub-agents (track/render tool runs).
- `src/app/orchestrator.js` / `src/app/agents.js` — orchestrator popover, and the **agent inspector**: a run record per sub-agent (Task) keyed by its `tool_use` id, kept outside `state.live` so a finished agent stays inspectable. Its chip opens a dedicated window with a live step-by-step timeline, token/step/elapsed tiles, the agent's report, and Stop (which ends the owning turn — the CLI can't kill one worker).
- `src/app/search.js` — sidebar search box + Saved (favorites) toggle.
- `src/app/messages.js` — assistant transcript building blocks: action chips (expand/diff/output), plan & AskUserQuestion cards, `renderSegments`.
- `src/app/stream.js` — composer input/autosize, the typewriter (`makeTyper`), concurrent per-thread streaming (`state.live`), `send`/`stopTurn` (first press interrupts and keeps the warm process; pressing stop again — or `STOP_ESCALATE_MS` of nothing happening — escalates to killing it), and the **suggested next message** strip (`--prompt-suggestions` → a `prompt_suggestion` event; it only arrives once a chat has history and only when the CLI has a confident guess, so the strip is a bonus, never a fixture).
- `src/app/mentions.js` — `#`-reference another chat from the composer: a `#` autocomplete over the project's chats, reference pills above the input, and `resolveComposerRefs` → thread ids passed as `refs` to the `chat` command (backend folds the referenced transcripts into the prompt as background context).
- `src/app/skills.js` — the **`/` picker**: type `/` at the head of a message to pick a Claude Code skill (`/code-review`, `/run`, a `.claude/skills` or `.claude/commands` entry of your own). Skills always worked in Krystal — nothing listed them. The list is merged from two halves: the backend scans the project's and the user's `.claude/skills`/`.claude/commands` for names *and descriptions* (`list_skills` → `skills.rs`), while the CLI names its own built-ins — which live inside the binary, not on disk — in every session's `system.init` event, forwarded on the `start` event and cached per project in localStorage. Blurbs for known built-ins live in `i18n.js` (`skillBlurb.*`); an unrecognised skill just shows its name.
- `src/app/attachments.js` — attach files by **paste or drag-and-drop** (no upload button): Ctrl+V a clipboard image (persisted to `<app_data_dir>/attachments/` via the `save_attachment` backend command) or drop files onto the window (Tauri drag-drop event → real paths). Queued as pills above the input; on send their paths ride along as `files` to the `chat` command (backend's `build_prompt` tells Claude to Read them — Claude Code reads images natively). Image chips get a thumbnail via `read_image`.
- `src/app/wizard.js` — Initialize wizard state machine (brief → analyze → questions → review → save) + the CLAUDE.md editor.
- `src/app/localization.js` — EN/HR flag toggle; re-renders dynamic surfaces on language change.
- `src/app/settings.js` — Discord presence + the Settings modal (tabs, feature switches, persisted in localStorage). `openSettings(tab)` can open straight onto one tab.
- `src/app/phone.js` — the **Phone** button + Settings → Phone panel (start/stop, the address and pairing code), and the **mirroring** of a turn started on the phone: it builds the liveTurn `send()` would have built and replays the backend's forwarded events through `handleLiveEvent`, so the typewriter, Activity panel, sidebar mark and Stop button all behave as if the message had been typed here.
- `src/app/tasks.js` — per-project to-do list: sidebar-foot Tasks button (open-count badge) + Tasks modal (add/rename/complete/delete/clear-done), plus a "generate from a description" flow that may ask clarifying questions then has Claude draft the tasks (`generate_tasks` backend command; stored in the SQLite `tasks` table keyed by project path). During chat, the backend drops a fresh markdown snapshot under `<app_data_dir>/task-lists/<key>.md` and appends a system-prompt note that **names the open tasks** (capped at `TASK_NOTE_TITLES`; their notes, the done items and the `(id:N)` markers stay in the file for Claude to `Read`). The note asks Claude to **keep the list current unasked** — tick a line off in that file as soon as the work finishing it lands. After the turn, on *every* exit path (including a stopped or failed one), `reconcile_task_snapshot` folds the file's edits back into SQLite and emits a `tasks` event that refreshes the badge/panel and shows a side-tip. See `prepare_task_awareness`/`write_task_snapshot`/`reconcile_task_snapshot` in `commands.rs`, with round-trip tests in that file's `mod tests`.
- `src/app/artifacts.js` — the **artifact panel**: the project's artifacts down the left, the chosen one rendered on the right. HTML and SVG run for real inside a `sandbox="allow-scripts"` iframe (no same-origin, so an artifact can be a live interactive page without being able to reach Krystal); markdown renders in the app's own typography. Two ways in: the card an artifact leaves in the transcript (a tool segment carrying `artifact`, rendered via `specialToolCard`) and the Artifacts button in the sidebar foot. A turn is **one version** however many times Claude patches the artifact while working — versions are what the user asked for, not what the tool did — so the panel drops version numbers while a turn is in flight and picks them back up from the DB when it lands (`artifactsTurnEnded`). Stored in the SQLite `artifacts` table keyed by project path and re-keyed by `move_project`, like pins. Save a copy / Open in browser are the sharing story: an artifact is self-contained by construction, so the saved file works anywhere, offline, on its own.
- **Mermaid diagrams** are the one kind stored as something other than what you see: Claude writes mermaid *source* (which lays the diagram out for it — far better than placing SVG shapes by hand), the DB keeps that source so `old_str` patches keep applying, and the frontend renders it to SVG for the panel and for Save / Open in browser. So the file you send someone is a few KB of SVG, not a renderer in a trench coat. `src/vendor/mermaid.min.js` (3.6 MB uncompressed, ~0.8 MB in the installer) is **loaded lazily** by `ensureMermaid()` the first time a diagram is opened — never at boot, never in a session with no diagrams. Known limit: mermaid's default `htmlLabels` puts labels in `<foreignObject>`, which every browser renders but some non-browser SVG tools (Inkscape, Word, GitHub's inline SVG) do not.
- `src/app/pins.js` — **pinned files**: a rail down the right edge of the chat holding files you want to glance at mid-conversation (a task list, a brief). Rests collapsed at low opacity over the gutter — absolutely positioned, so it never takes layout space — opens on hover (one property animates: the chip's `max-width`), and a click reads the file **fresh** into a light overlay (markdown rendered, anything else as plain text). Pins are **per project**, stored in the SQLite `pins` table keyed by project path, and `move_project` rewrites any that lived inside the folder. Backend: `list_pins`/`add_pin`/`remove_pin`/`read_pinned_file` in `commands.rs`.
- `src/app/git.js` — git status line + branch picker (switch/create/fetch/pull/push).
- `src/app/links.js` — intercepts reply links; opens via browser / ask-each-time / in-app viewer.
- `src/app/logo.js` — RYSTAL wordmark per-letter split, logo intro + idle "living logo" glow.
- `src/app/usage.js` — Claude subscription usage (5h + weekly): scans local history via the `claude_usage` backend command, calibrate-once percentages, header chip + Settings tab + limit-warning tips.
- `src/app/boot.js` — entry point: runs the startup sequence (loads **last**).

## Language & communication
- When developing Krystal in this repo, **reply in English** (match the codebase and README).
- The app UI itself supports **EN + HR**.

## Conventions
- **Frontend stays vanilla JS** — no framework, no bundler. Preserve the single-exe simplicity.
- **Match the surrounding style**; keep dependencies minimal.
- Keep files cohesive as they are (the `claude.rs` / `commands.rs` / `db.rs` split on the Rust side; the per-concern `src/app/*.js` modules on the frontend). When adding UI, put it in the module that owns that concern rather than growing one file back into a monolith.
- Prefer **small, readable changes** over large refactors.

## i18n
- For **every new user-facing string, add both EN and HR** — never leave one locale behind.
- Keep **Croatian output gender-neutral**. Always use UTF-8 so č/ć/ž/š/đ are preserved exactly.

## Motion & animation
- **Every new feature/UI element should carry the app's clean, polished, *subtle* motion** where it's appropriate (opens/closes, hovers, state changes, transitions) — never ship a raw cut where a small animation fits.
- Match the established style: short durations (~.15–.35s), gentle spring/ease curves (e.g. `cubic-bezier(.2,.9,.3,1.25)`), small offsets — taste over flash. Reuse existing helpers/patterns (`replayClass`, `openOverlay`/`closeOverlay`, the `.panel-swap`/`.list-swap` crossfades, `prefers-reduced-motion` guards) rather than inventing new ones.
- **Always add a `@media (prefers-reduced-motion: reduce)` fallback** for any non-trivial animation.
- Default state should be the *resting* state: don't let an animation hook (e.g. an expandable panel) change an element's collapsed size/footprint when idle.
- **Restraint — don't go overboard.** Animate **one** thing calmly (usually a size/position slide), not a stack of properties at once. Never morph an element's **shape** (e.g. `border-radius` pill→box) *during* a size change — it reads as a weird springing/ellipse; let shape and width **snap** instead. Reserve springy/overshoot curves for tiny accents (a star pop), never for an open/close — use a plain `ease` there. When unsure, do less.
